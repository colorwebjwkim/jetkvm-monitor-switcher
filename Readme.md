# jetkvm-monitor-switcher

JetKVM 사용 환경에서 모니터 구성을 전환하는 Windows 트레이 프로그램입니다.
평소에는 전체 모니터를 사용하고, 원격 접속 중에는 JetKVM 연결 화면만 켜거나
다른 모니터와 같은 화면을 표시할 수 있습니다.

## 프로젝트 목적

JetKVM으로 PC에 원격 접속할 때마다 Windows 디스플레이 설정에서 모니터를
끄거나 복제하고, 사용 후 원래 배치로 되돌리는 반복 작업을 줄이기 위한 프로젝트입니다.

여러 모니터를 사용하는 PC에서는 원격 접속 시 JetKVM에 연결된 화면을 중심으로
작업하고, PC 앞에서 직접 사용할 때는 평소의 전체 모니터 구성을 복원하는 것이
목표입니다. 트레이와 바로가기로 직접 전환하거나 MQTT 접속 상태에 따라 자동으로
전환할 수 있습니다. 필요하면 원격 화면을 일반 모니터에도 복제하여 함께 확인합니다.

이 프로젝트의 범위는 **JetKVM 사용에 맞춘 Windows 모니터 구성 전환**입니다.
원격 접속 서비스, JetKVM 펌웨어 또는 모니터 물리적 전원 제어를 대체하지 않습니다.

## 주요 기능

- **집 모드**: 저장한 전체 모니터의 배치와 해상도 복원
- **외부 모드**: 선택한 모니터만 활성화하거나 JetKVM과 일반 모니터의 화면 복제
- **빠른 전환**: 트레이 클릭, 바탕화면 바로가기, 키보드 단축키
- **접속 자동 전환**: JetKVM의 MQTT 접속 수에 따라 화면 구성 변경
- **로그인 시 실행**: 현재 사용자 Windows 자동 실행 설정
- **비정상 종료 복구**: 별도 감시 프로세스가 3초 뒤 앱 재실행

Windows DisplayConfig API로 화면 연결 구성을 변경합니다.
모니터의 물리적 전원이나 JetKVM의 원격 제어 기능은 조작하지 않습니다.

## 요구 사항

- Windows 및 .NET 10 SDK(소스 빌드 시)
- 64비트 Windows(아래 배포 명령과 바탕화면 아이콘 배치 기준)
- 접속 자동 전환 사용 시 MQTT 상태 전송이 가능한 JetKVM과 LAN 연결

독립 실행 배포본에는 .NET 런타임이 포함됩니다.
화면 복제 지원 여부는 그래픽 어댑터와 모니터 구성에 따라 달라집니다.

## 빌드와 실행

프로젝트 폴더에서 실행합니다.

```powershell
dotnet build -c Release
dotnet run -- --dev
```

배포본 생성:

```powershell
dotnet publish -c Release -r win-x64 --self-contained true -o publish
.\publish\jetkvm-monitor-switcher.exe
```

`publish` 폴더 전체를 유지하세요. 자동 실행과 바로가기는 실행 파일 경로를
참조하므로 설치 폴더를 옮기면 다시 설정해야 합니다.

빌드 산출물 이름은 `jetkvm-monitor-switcher.exe`, `jetkvm-monitor-switcher.dll`,
`jetkvm-monitor-switcher.deps.json`, `jetkvm-monitor-switcher.runtimeconfig.json`입니다.
배포 ZIP 이름은 `jetkvm-monitor-switcher-win-x64.zip`을 사용합니다.
이전 버전에서 교체할 때는 트레이 메뉴에서 종료한 뒤 새 실행 파일을 실행하고,
로그인 자동 실행 설정과 바탕화면 바로가기를 다시 저장하세요.
방화벽 규칙도 새 실행 파일 경로로 다시 설정해야 합니다.
설정 폴더와 내부 통신 식별자는 `jetkvm-monitor-switcher`를 사용합니다.
이전 이름의 설정 폴더는 자동으로 읽지 않으므로 새 버전에서 모니터와 MQTT 설정을
다시 저장하세요. 이전 버전의 로그인 자동 실행 항목도 해제한 뒤 교체하세요.

프로젝트의 `bin` 실행 파일은 배포본이 있으면 `publish/jetkvm-monitor-switcher.exe`에
실행을 전달합니다. 개발본을 직접 실행할 때는 `--dev`를 사용하세요.
배포본과 개발본은 동일 Windows 세션에서 트레이 단일 인스턴스를 공유합니다.

## 처음 설정하기

1. 사용할 모니터를 모두 연결하고 Windows에서 활성화합니다.
2. 프로그램을 실행하고 설정 창에서 외부 모드에 사용할 모니터를 선택합니다.
   JetKVM 이름이 감지되면 기본 선택됩니다.
3. 필요하면 화면을 복제할 일반 모니터와 Windows 자동 실행을 선택합니다.
4. **저장**을 누릅니다. 저장 전 화면 구성의 적용 가능 여부를 검증합니다.

모니터를 추가하거나 전체 배치를 변경했다면 집 모드에서 **설정 → 현재 전체
모니터 구성 다시 읽기 → 저장**을 실행하세요.

### 트레이와 바로가기

| 조작 | 동작 |
| --- | --- |
| 트레이 아이콘 왼쪽 클릭 | 집/외부 모드 전환 |
| 트레이 아이콘 오른쪽 클릭 | 모드, 설정, 자동 감지, 바로가기, 종료 메뉴 |
| 초록색 집 아이콘 | 집 모드 |
| 주황색 지구본 아이콘 | 외부 모드 |
| `Ctrl+Alt+H` | 집 모드 바로가기 |
| `Ctrl+Alt+E` | 외부 모드 바로가기 |

**바탕화면 바로가기 추가**는 켜진 각 모니터에 바로가기를 한 쌍씩 생성하고
배치합니다. 기본 화면의 바로가기에 키보드 단축키가 지정됩니다.
이 과정에서 바탕화면 아이콘 자동 정렬을 해제하며 기존 아이콘은 직접 이동하지
않습니다. 단축키는 Windows Explorer가 처리하므로 다른 프로그램과 충돌할 수 있습니다.

### 외부 모드 화면 복제

설정의 **외부 모드에서 같은 화면을 표시할 모니터**에서 선택합니다.

- **없음**: 선택한 외부 모니터 한 대만 활성화합니다.
- **일반 모니터 선택**: JetKVM과 선택한 모니터만 켜고 같은 주 화면을 표시합니다.
  이 경우 외부 모드의 주 모니터로 JetKVM을 선택해야 합니다.

복제는 같은 그래픽 어댑터의 출력 사이에서 지원하며 공통 해상도와 주사율이
선택될 수 있습니다. 외부 모드에서 저장하면 즉시 반영되고 집 모드에서 저장하면
다음 외부 모드 전환 때 적용됩니다. 집 모드의 전체 구성은 별도로 유지됩니다.

## JetKVM 접속 자동 전환

내장 MQTT 수신기를 사용하므로 별도 MQTT 서버는 필요하지 않습니다.
초기 상태에서는 자동 감지가 꺼져 있으며 네트워크 주소는 지정되어 있지 않습니다.

1. 앱을 한 번 실행하여 모니터 설정을 저장한 뒤 트레이 메뉴에서 **종료**합니다.
2. `%LOCALAPPDATA%\jetkvm-monitor-switcher\settings.json`의 아래 필드를 수정합니다.
   기존 모니터 설정과 다른 필드는 그대로 유지하세요.
3. JetKVM의 MQTT 설정에서 Broker Address를 PC 주소로, Port를 같은 포트로
   지정합니다. Remote Control은 끄고 저장·재연결합니다.
4. 방화벽을 설정한 뒤 앱을 실행하고 **JetKVM 접속 자동 전환**을 켭니다.
   **자동 감지 상태** 메뉴와 JetKVM의 Connected 표시를 확인합니다.

| 설정 필드 | 값 |
| --- | --- |
| `JetIp` | JetKVM의 실제 IPv4 주소 |
| `ReceiverIp` | PC의 실제 LAN IPv4 주소 |
| `ReceiverPort` | MQTT 수신 포트, 기본 `1883` |
| `JetAuto` | 자동 감지 활성화 여부 |

주소 변경 후에는 앱을 재시작하고 JetKVM 및 방화벽 설정도 맞춰야 합니다.
로그인 직후 PC 수신 IP가 아직 할당되지 않았으면 2초 간격으로 최대 30회 재시도합니다.
주소 형식이나 포트 오류는 **JetKVM 자동 감지 설정 확인**으로 안내하며,
모니터 구성 오류와 구분합니다. 수신 실패 중에는 접속 상태를 근거로 화면을 전환하지 않습니다.
수신기는 지정한 JetKVM IP만 허용하며 메시지 구독과 중계는 거부합니다.
상태 전송은 TLS 없이 동작하므로 신뢰할 수 있는 LAN에서 사용하세요.

### 방화벽 설정

관리자 PowerShell에서 실행합니다. 아래 주소는 문서용 예시이며 실제 LAN 주소로
바꿔야 합니다. 먼저 `-WhatIf`로 변경 내용을 확인할 수 있습니다.

```powershell
.\Configure-Firewall.ps1 -JetIp 192.0.2.10 -ReceiverIp 192.0.2.20 -WhatIf
.\Configure-Firewall.ps1 -JetIp 192.0.2.10 -ReceiverIp 192.0.2.20
```

기본 실행 파일 경로는 스크립트 옆 `publish/jetkvm-monitor-switcher.exe`입니다.
다른 위치에 설치했으면 `-ExecutablePath`를, 다른 포트를 사용하면 `-Port`를
지정하세요. 지정한 실행 파일·JetKVM IP·PC IP·TCP 포트만 허용합니다.
동일 이름의 기존 허용 규칙은 교체합니다.

해당 실행 파일의 인바운드 TCP 차단 규칙을 비활성화해야 하는 경우에만
`-DisableConflictingBlocks`를 추가하세요. 기본 실행은 차단 규칙을 변경하지 않습니다.

### 자동 전환 정책

- 접속자가 있으면 외부 모드로 전환합니다.
- 접속 수가 0명인 상태가 10초간 유지되면 집 모드로 복원합니다.
- 수신 중단, 잘못된 메시지, 마지막 수신 후 45초 경과는 상태 미확인으로 처리하고
  현재 모드를 유지합니다.
- 수동 전환 후에는 같은 접속 상태가 유지되는 동안 자동으로 다시 전환하지 않습니다.
  다음 접속/종료 변화에서 자동 전환을 재개합니다.
- 일반 실행과 로그인 실행은 집 모드를 먼저 적용한 뒤 자동 전환을 시작합니다.

## 종료와 자동 복구

충돌 또는 트레이 앱 강제 종료 시 감시 프로세스가 3초 뒤 재실행하고 저장된
마지막 화면 모드를 복원합니다. 실행 중 앱과 감시 프로세스가 각각 표시되는 것은 정상입니다.

트레이 메뉴의 **종료**는 감시도 종료하므로 앱이 다시 실행되지 않습니다.
감시 프로세스까지 함께 종료하거나 Windows를 로그아웃/종료하면 복구하지 않습니다.
프로세스가 살아 있는 상태의 응답 없음은 감지하지 않습니다.
다음 로그인 시 실행은 Windows 자동 실행 설정에 따릅니다.

## 명령줄과 검증

| 옵션 | 동작 |
| --- | --- |
| `--home` | 집 모드 적용, 실행 중이면 기존 앱에 전달 |
| `--outside` | 외부 모드 적용, 실행 중이면 기존 앱에 전달 |
| `--install-shortcuts` | 바탕화면 바로가기 생성·배치 |
| `--ping` | 기존 앱의 명령 수신 확인 |
| `--diagnose` | 현재 화면 조회와 적용 가능 여부 검증, 화면 변경 없음 |
| `--self-test` | 모니터 구성 생성과 접속 정책, 로컬 MQTT 자체 검증 |
| `--validate-clones` | 저장된 구성의 각 JetKVM 복제 조합 검증, 화면 변경 없음 |
| `--probe-clone` | **실제 화면 변경**으로 복제를 검증한 뒤 원래 구성 복원 시도 |
| `--dev` | 개발 실행 파일의 배포본 전달 생략 |

자체 검증은 실제 화면 구성을 변경하지 않으며 로컬 TCP 포트 `18884`를 사용합니다.
결과는 실행 파일 옆 `self-test.json`에 기록합니다.

```powershell
.\publish\jetkvm-monitor-switcher.exe --self-test
.\publish\jetkvm-monitor-switcher.exe --diagnose
```

자체 검증 통과와 실제 JetKVM 연결·화면 전환·로그인 동작 확인은 별개입니다.
실제 화면 전환과 복제는 사용할 하드웨어 환경에서 확인하세요.
`--startup`, `--recover`, `--watchdog`는 앱 내부에서 사용하는 실행 옵션입니다.
설정 보조 옵션 `--enable-jet-auto`와 `--select-jet-monitor`는 설정 파일을 변경하므로
앱이 종료된 상태에서만 사용하세요. 일반 사용에서는 설정·트레이 메뉴를 이용합니다.

## 설정과 문제 해결

- 설정: `%LOCALAPPDATA%\jetkvm-monitor-switcher\settings.json`
- 접속 상태·실행 경로·마지막 전환 오류: 같은 폴더의 `jet-status.json`
- 로그인 자동 실행: 현재 사용자 레지스트리
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
- 진단·자체 검증·바로가기 배치 결과: 실행 파일 옆 JSON 파일

로그인 자동 실행 항목 이름도 `jetkvm-monitor-switcher`입니다.

저장 시 모니터 장치 경로를 보관하고 적용 전에 현재 그래픽 어댑터 식별자로 다시
연결하므로 재부팅으로 어댑터 식별자가 바뀌어도 저장한 배치와 해상도를 유지합니다.
이전 설정은 단일 어댑터에서 기존 출력 번호가 모두 확인될 때만 이전하며,
다중 어댑터 등 식별이 모호하면 설정 창에서 전체 구성을 다시 읽고 저장하세요.
로그인 직후 적용 실패는 2초 간격으로 최대 30회 재시도합니다. 실패해도 모니터
설정을 삭제하거나 강제로 전체 확장하지 않으며 현재 화면을 유지하고 자동 전환을
대기합니다. 연결이 안정된 후 트레이에서 집 모드를 다시 적용할 수 있습니다.
설정 파일 자체를 읽을 수 없는 경우에는 `.backup-날짜-시간`으로 백업하고 설정
창을 표시합니다. 새 모니터 구성은 사용자가 저장해야 반영됩니다.

자동 감지가 켜져 있지만 상태를 30초 이상 받지 못하면 ‘감지 대기’와 연결 확인
알림을 표시합니다. JetKVM의 MQTT Connected 상태, IP·포트, 방화벽 설정을 확인하세요.
Disconnected이면 JetKVM에서 Save & Reconnect를 실행하세요.

## 소스 구성

| 파일 | 역할 |
| --- | --- |
